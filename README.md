# Daily QC Operation Report (AHR) v1.1.1

โปรแกรมรวมข้อมูลงาน QC จากทุก Line ทุกกะ แล้วสรุปเป็นรายงานรายวัน รายเดือน หรือช่วงเวลาที่เลือก ประกอบด้วย 2 โปรแกรมย่อย

1. **QC Inspection Report** : QC ประจำ Line กรอก Production / QC Check / OK / NG / NC ของแต่ละ Part ต่อกะ ทำรายงานส่ง Assembly ในรูปแบบเดียวกับไฟล์ `QC Inspection Report (OK-NC-NG)` เดิม
2. **QC Report Quality Issue** : QC แจ้งปัญหาภายในและปัญหาจากลูกค้าพร้อมรูปหลักฐาน ทำรายงานแบบ `Weekly report AHR` เดิม ให้ Assembly ลง Root Cause / Correction / Prevention

---

## 1. ทดสอบบนเครื่อง PC (Windows)

ต้องมี **Python 3.10 ขึ้นไป** (ตอนติดตั้งให้ติ๊ก "Add python.exe to PATH")

ใช้ได้ทั้งบน PC, Tablet และมือถือ: จอกว้างตั้งแต่ 1200px เมนูอยู่ด้านซ้ายและพับเก็บได้ด้วยปุ่มสามขีด จอที่แคบกว่านั้นเมนูจะซ่อนไว้และเปิดด้วยปุ่มสามขีดมุมซ้ายบน ส่วน ออกจากระบบ / ปิดโปรแกรม อยู่ที่ปุ่มวงกลมมุมขวาบน

| ต้องการ | วิธี |
|---|---|
| เปิดโปรแกรม | ดับเบิลคลิก `start.bat` ครั้งแรกจะติดตั้งให้เอง 1-3 นาที (ต้องต่อเน็ตครั้งเดียว) แล้วเบราว์เซอร์จะเปิดขึ้นมาเอง |
| ปิดโปรแกรม | ดับเบิลคลิก `stop.bat` หรือในโปรแกรมกดปุ่มวงกลมมุมขวาบน > **ปิดโปรแกรม** (เฉพาะ Admin) |
| ออกจากระบบ | กดปุ่มวงกลมมุมขวาบน > **ออกจากระบบ** |
| เข้าครั้งแรก | ผู้ใช้ `admin` รหัสผ่าน `admin1234` ระบบจะบังคับให้ตั้งรหัสใหม่ทันที |
| ให้เครื่องอื่นใน LAN ใช้ด้วย | เปิด `http://<IP ของเครื่องนี้>:8790` (IP แสดงในหน้าต่าง server ที่ย่ออยู่) ถ้าเข้าไม่ได้ให้อนุญาต Python ใน Windows Firewall |
| เปลี่ยน Port | คัดลอก `.env.example` เป็น `.env` แล้วแก้ `PORT=` |

ข้อมูลทั้งหมด (รวมรูป) อยู่ในไฟล์เดียวคือ `data/dailyqc.db` ฟอนต์และกราฟฝังในโปรแกรม ใช้ได้โดยไม่ต้องต่ออินเทอร์เน็ต

### ข้อมูลตัวอย่าง
เมนู **สำรองข้อมูลและรูป > ใส่ข้อมูลตัวอย่าง** จะใส่ผลตรวจสมมุติย้อนหลังประมาณ 3 สัปดาห์ และ 9 เคสจากไฟล์ Weekly report ที่ส่งมา (ย้ายวันที่มาเป็นสัปดาห์นี้) พร้อมบัญชีทดสอบ `demo_qc` / `demo_sup` / `demo_asm` รหัส `demo1234` ลบออกได้ที่ปุ่ม **ลบข้อมูลตัวอย่าง** ในหน้าเดียวกัน
**ต้องลบข้อมูลตัวอย่างก่อนใช้งานจริง** ตัวเลขผลตรวจเป็นตัวเลขสุ่ม ไม่ใช่ข้อมูลจริงของโรงงาน

## 2. การใช้งานประจำวัน

### QC Inspection Report
- **บันทึกผลตรวจประจำกะ** : เลือกวันที่ กะ Line ลูกค้า แล้วกรอกตัวเลขในตาราง
  - พิมพ์ Production แล้ว QC Check จะตามให้ (ปิดได้ที่ช่องติ๊กด้านบน) และ OK = QC Check - NG - NC คำนวณให้ แก้เองได้
  - กด Enter เพื่อลงไปช่องเดียวกันของ Part ถัดไป
  - ปุ่ม **อาการเสีย** ใช้แจกแจง NG / NC ตามอาการ ข้อมูลนี้คือที่มาของกราฟ Pareto
  - ถ้า OK + NG + NC ไม่เท่ากับ QC Check ระบบจะเตือนแต่ยังบันทึกได้
  - ลบตัวเลขของ Part จนว่างแล้วกดบันทึก = ลบรายการนั้น
- **ข้อมูลที่บันทึกแล้ว** : ค้นหา แก้ไข ลบ และ Export Excel ตามช่วงเวลา
- **รายงานส่ง Assembly** : ตารางแบบไฟล์เดิม (Part x วันที่ x กะ D/N) แยกลูกค้า พร้อมตารางอาการเสียและ Pareto กด Export Excel หรือพิมพ์เป็น PDF ได้
- **กราฟวิเคราะห์** : แนวโน้ม OK/NG/NC, % NG / % NC, Production เทียบ QC Check, Pareto, Part ที่เสียมากที่สุด, เทียบลูกค้า เทียบ Line เทียบกะ เลือกช่วงเวลาและแยกลูกค้าได้

ไฟล์ Excel ของ QC Inspection มี Sheet: `Summary` (ตาราง + กราฟ), Sheet ของแต่ละลูกค้าพร้อมรูป Part, `<ลูกค้า> กราฟ` (อาการเสีย x Part + กราฟ), `Data` และ `Defect detail` (ข้อมูลดิบจากฐานข้อมูล)

### QC Report Quality Issue
- **แจ้งปัญหาที่พบ** : เลือกพบภายใน / ลูกค้าแจ้ง, Part, อาการเสีย, จำนวน แล้วถ่ายรูปหรือเลือกรูป (สูงสุด 8 รูปต่อเคส ระบบย่อรูปให้ก่อนส่ง) ติดป้าย NG / OK ที่รูปได้
- **รายการเคส** : ค้นหา กรองตามลูกค้า สถานะ แหล่งที่พบ
- หน้าเคส : ผู้มีสิทธิ์วิเคราะห์ลง QA/QC Action, Root Cause, Correction, Prevention, Plan / Actual date และเปลี่ยนสถานะ เปิดอยู่ / กำลังแก้ไข / ปิดแล้ว
- **รายงานสรุปพร้อมรูป** : หน้าตาแบบ Weekly report เดิม เลือกช่วงเวลาได้ Export Excel พร้อมรูป หรือพิมพ์เป็น PDF
- **กราฟวิเคราะห์** : จำนวนเคสตามเวลา, ภายในเทียบลูกค้า, Pareto อาการเสีย, อาการเสียแยกลูกค้า, สถานะ, จุดที่พบ, Part ที่เกิดซ้ำ

### ภาพรวม
หน้าแรกสรุปทั้งสองโปรแกรมย่อย เลือกดู **รายวัน / รายเดือน / ช่วงเวลา** ได้ ในมุมมองรายวันจะเห็นว่า Line ไหนกะไหนยังไม่ส่งข้อมูล

## 5. การแจ้งเตือนและรายงานอัตโนมัติ

เมนู **ช่องทางแจ้งเตือน**
- **Email** เลือกวิธีส่งได้ 3 แบบ
  - SMTP : Gmail ใช้ `smtp.gmail.com` port 587 STARTTLS และ App password (ต้องเปิด 2-Step Verification ก่อน) เหมาะกับการรันบน PC
  - Brevo API / Resend API : ส่งผ่าน HTTPS ใช้บน Host ฟรีที่ปิด port SMTP ได้
- **LINE** : ใช้ LINE Official Account (Messaging API) ใส่ Channel access token และ User ID / Group ID (LINE Notify ปิดบริการไปแล้ว)
- **Telegram** : Bot token + Chat ID ส่งรูปและไฟล์ Excel ได้
- **Discord** : Webhook URL ส่งรูปและไฟล์ได้
- **Webhook ทั่วไป** : เช่น Microsoft Teams รับ JSON `{title, text}`
- **ในโปรแกรม** : รูปกระดิ่งมุมขวาบน

เหตุการณ์ที่แจ้งทันที: มี Quality Issue ใหม่ (พร้อมรูปแรก), NG + NC เกินเกณฑ์ที่ตั้ง, รูปใกล้ครบกำหนดลบ แต่ละเรื่องเลือกช่องทางและอีเมล To / CC แยกกันได้ มีปุ่มทดสอบส่งทุกช่องทาง

เมนู **ส่งรายงานอัตโนมัติ**
- ตั้งชื่อ เลือกเนื้อหา (Inspection / Quality Issue) ช่วงข้อมูล (เมื่อวาน สัปดาห์ก่อน เดือนก่อน ฯลฯ) ความถี่ วัน เวลา ช่องทาง To / CC และแนบ Excel
- มีตัวอย่างให้ 4 รายการ (ปิดอยู่): รายงานรายวัน 08:30, Weekly Quality Issue วันจันทร์, สรุปรายเดือนวันที่ 1, เตือน Line ที่ยังไม่ส่งข้อมูลกะ Day
- ปุ่ม **ส่งตอนนี้** ใช้ทดสอบได้ทันที
- ถ้าเครื่องปิดอยู่ตอนถึงเวลา รายงานจะส่งเมื่อเปิดโปรแกรมภายใน 12 ชั่วโมง

## 6. รูป 45 วัน และการสำรองข้อมูล

- รูปของ Quality Issue เก็บขนาดเต็มไว้ตามจำนวนวันที่ตั้ง (สูงสุด 45 วัน) แล้วลบอัตโนมัติทุกวันหลัง 00:30
- **ข้อความของเคสและผลตรวจทั้งหมดไม่ถูกลบ** และเลือกให้เก็บรูปย่อขนาดเล็กไว้ดูอ้างอิงได้
- ก่อนถึงกำหนด ระบบเตือน Admin ล่วงหน้า (ค่าเริ่มต้น 7 วัน) และเลือกให้แนบ ZIP รูปไปกับอีเมลได้
- เมนู **สำรองข้อมูลและรูป**
  - **สำรองทั้งหมด พร้อมรูป** : ZIP เดียว มีข้อมูลทุกตาราง รูปทุกรูป และไฟล์ Excel สำหรับเปิดอ่าน
  - **รูปที่ใกล้ครบกำหนด / รูปทั้งหมด** : ZIP จัดโฟลเดอร์ตามเดือนและเลขเคส พร้อม `index.csv`
  - **กู้คืนจากไฟล์สำรอง** : แทนที่ข้อมูลทั้งหมดด้วยไฟล์ (ต้องพิมพ์ RESTORE ยืนยัน)
- บนเครื่อง PC โปรแกรมสร้างไฟล์สำรองเต็มชุดทุกวันใน `data/backups` (เก็บ 14 ไฟล์ล่าสุด) โดยทำก่อนลบรูป

## 7. ขึ้น Host ฟรี (Render + Neon)

ขั้นตอนละเอียดทีละคลิกอยู่ในไฟล์ **`HOSTING_GUIDE_TH.md`** สรุปสั้น ๆ คือ

1. สร้างฐานข้อมูล PostgreSQL ฟรีที่ neon.tech แล้วคัดลอก Connection string
2. นำโค้ดขึ้น GitHub (Private) โดยให้ `app`, `seed_data`, `requirements.txt` อยู่ชั้นแรกสุดของ Repository
3. Render: New > Blueprint > เลือก Repository แล้วใส่ `DATABASE_URL` และ `ADMIN_PASSWORD`
4. Login แล้วใส่ที่อยู่เว็บใน **ตั้งค่าโปรแกรม**
5. ย้ายข้อมูลจาก PC ด้วย สำรองทั้งหมด > กู้คืนจากไฟล์สำรอง
6. อีเมลบน Host ฟรีต้องเลือกวิธีส่ง **Brevo API** หรือ **Resend API** เพราะ Render แบบ Free ปิด port SMTP
7. ตั้ง cron-job.org ให้เรียก `/cron/tick?key=...` เพื่อให้รายงานอัตโนมัติออกตรงเวลา

สิ่งที่โปรแกรมทำไว้ให้เข้ากับ Host ฟรี
- รูปและข้อมูลทั้งหมดอยู่ในฐานข้อมูล ไม่มีไฟล์ค้างบนดิสก์ของ Host
- ตอนที่ไม่มีงาน โปรแกรมไม่ถามฐานข้อมูลเลย ฐานข้อมูลฟรีจึงหลับได้และไม่เปลืองโควตา
- ถ้าขึ้น Host โดยไม่ใส่ `DATABASE_URL` จะมีแถบสีแดงเตือน Admin ว่าข้อมูลจะหายเมื่อรีสตาร์ต
- บน Host ไม่มีปุ่มปิดโปรแกรม และไม่มีการสำรองลงดิสก์ ให้ดาวน์โหลดไฟล์สำรองเก็บเองเป็นระยะ

## 8. อัปเดตเป็นเวอร์ชันใหม่โดยข้อมูลไม่หาย
- **PC** : ปิดโปรแกรม คัดลอกไฟล์เวอร์ชันใหม่ทับ (ไม่ต้องแตะโฟลเดอร์ `data` และ `.venv`) แล้วเปิด `start.bat`
- **Host** : push โค้ดใหม่ขึ้น GitHub
- เมื่อเริ่มทำงาน โปรแกรมจะเพิ่มตารางและคอลัมน์ใหม่ให้เองโดยไม่ลบข้อมูลเดิม

| `start.bat` แจ้งว่าไม่พบ Python | ติดตั้ง Python 3.10+ และติ๊ก Add to PATH แล้วเปิด Command Prompt ใหม่ |
| ติดตั้งแพ็กเกจไม่ผ่าน | ตรวจอินเทอร์เน็ต / Proxy ของโรงงาน ลบโฟลเดอร์ `.venv` แล้วเปิด `start.bat` ใหม่ |
| เปิดแล้วเบราว์เซอร์ไม่ขึ้น | เปิด `http://localhost:8790` เอง หรือดูข้อความในหน้าต่าง server ที่ย่ออยู่ |
| Port 8790 ถูกใช้อยู่ | ตั้ง `PORT=8791` ในไฟล์ `.env` |
| ลืมรหัส admin | ให้ Admin คนอื่นตั้งรหัสใหม่ในเมนูผู้ใช้งาน ถ้าไม่มี บน PC ให้ปิดโปรแกรมแล้วเปิด `reset_admin.bat` (รหัสจะกลับเป็น `admin1234`) |
| อีเมลไม่ออก | ดูสาเหตุที่ตารางท้ายหน้า **ช่องทางแจ้งเตือน** หรือเมนู **ประวัติการใช้งาน > การส่งแจ้งเตือน** |
